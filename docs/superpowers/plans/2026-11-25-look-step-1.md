# The look, step 1: tokens and the workhorse page: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the workhorse page look B ("soft tiles") in light, dark and Increase Contrast, with every colour, size, word and rule it needs held in MacMoshKit under test, and CI pictures in light and dark on macOS 15 and 26.

**Architecture:** Two pull requests. 1a adds `Sources/MacMoshKit/Look/` (tokens as plain numbers, a WCAG 2 contrast function, the table of text-on-background pairs, sizes, button kinds) and new model fields beside today's (the state pill, a result flag carried through `MenuRefresher`, per-window tab counts, a desk row's cells, state cell, second line and spoken label); nothing a person sees changes. 1b draws them (one colour file on an `NSColor` dynamic provider, four `ButtonStyle`s, the header, the result slot, the desk row, the foot) and adds a dark pictures job, a minimum-size picture and a Tab check to CI.

**Tech Stack:** Swift 6 package, macOS 15+, SwiftUI and AppKit only, Swift Testing; bash and GitHub Actions for CI.

**Spec:** `docs/superpowers/specs/2026-11-25-look-design.md` (step 1 is section 14 item 1; its parts are sections 3, 5, 6.1, 6.3, 6.4, 6.5, 12 and 13).

## Global Constraints

- **Platform:** macOS 15.0 minimum stays (`Package.swift`, `App/Info.plist`, `AppBundleTests`); anything macOS 26 only needs a macOS 15 path.
- **Native only:** SwiftUI and AppKit; no third-party library, app or tool; no asset catalog.
- **Allowed controls** (design 3): Button, Text, TextField, Toggle, radio-group or segmented `Picker`, `List`. Never `ProgressView`, `Form`, `DisclosureGroup`, `Menu`, a pop-up, `contextMenu` or `.toolbar`. Stacks, `Grid`, `ViewThatFits`, shapes and custom `ButtonStyle`s are layout, not controls.
- **Shared words stay:** titles, state names, headlines and hints from `WorkhorseBlock` and `ButtonRules` do not change; `Tests/MacMoshKitTests/Fixtures/menu/*.txt` is not touched; `theMenuAndTheBoardShareTheirButtonsForEverySampleState` stays green unchanged.
- **New words, exactly:** "Made by hand" (help tag: today's "Not made with MacMosh: folder and restart not known") and "Closed". No other row of design section 7 is in this plan.
- **What CI reads stays:** every `WindowMarks` identifier on the element a click lands on; `page.headline` reads `StatusFormat.headline` ("Attic · Ready", "Spare · Locked after a restart"); a desk row is one AXButton whose label starts "name, window names, "; `page.result` holds the sentence alone; `page.listProblem`, `page.addMac` and the title "MacMosh" stay.
- **Size:** default 880 by 680, minimum 700 by 440.
- **Contrast:** every pair in `Look.pairs` reaches 4.5:1 in light and dark and 7:1 with increased contrast; a value that falls short moves until it passes, and the pull request lists each with its before and after.
- **Never colour alone:** every state has words; cells, tiles, dots, ticks and glyphs are hidden from VoiceOver.
- **Views stay thin:** every number, word and rule is in MacMoshKit with a test; the app target has no tests and is checked by CI's pictures, read by a person.
- **No motion of our own,** and no app-specific appearance switch (design 5.1, 6.11).
- **Placeholders only** in tests, samples and pull requests (Workhorse, Attic, Spare; api, blog, garden, notes, shop, website, recipes).
- **Outside facts from current sources,** cited in the pull request: the WCAG relative-luminance definition, the keyboard-navigation default's value, `EnvironmentValues.isFocused`.
- **Rollout:** nothing reaches the owner's daily Mac without his go-ahead; he tries step 1 after 1b merges.
- **Every task:** on the part's branch (`look/1a-tokens-and-model`, `look/1b-workhorse-page`), never `main`; test first, watch it fail, one commit per task; tests use `Paths.test` or `temporaryPaths()` and temporary folders, never `Paths.standard()`.
- **Every pull request:** `scripts/check.sh`, then `git diff main... | ask.sh review` with each finding answered; names the issue it is part of; description through the unslop pass (compared with the draft) and ending with the attribution lines; an entry in `docs/build-log.md` with the time read from `date`.

## Review Focus

Five inputs the design implies that no listed test exercises, most likely first; each is pinned in the task named.

1. **A desk with a very long name** (45 characters and more): never wraps, cut at 200 points with the whole name as help tag, whole in the spoken label, and the second line keeps its facts. Task A6 `aLongNameStaysWholeAndTheSecondLineKeepsItsFacts`.
2. **A desk with nine windows:** five cells and the small plus, never nine, while the state words count every tab. Task A5 `nineWindowsShowFiveCellsAndThePlus`.
3. **An older workhorse script, or the Tabs connection** (per-window tabs unknown): as many lit cells as tabs, at most one per window, from the first. Task A5 `withoutPerWindowCountsTheCellsLightFromTheFirst`.
4. **Increase Contrast in dark:** the high-contrast dark appearance picks the dark increased table, not the light one or plain dark. Task A1 `theAppearanceNamesPickTheirTables`.
5. **A failed result with a long sentence:** the failure flag reaches the page, the whole sentence stays the value and help tag, the slot gives it two lines. Task A4 `aLongFailedResultKeepsItsWholeSentenceInTwoLines` and the flag lines added to the runner tests.


## Decisions on the plan's open points

The coordinator settled these on 2026-11-25. Where a task below says otherwise, this section wins.

1. **A timed-out action is neither done nor failed.** `ResultKind` has three cases: `done`, `failed` and `unknown`. The runner's timed-out call sets `unknown`. The result slot draws `unknown` with a neutral mark and secondary words, never the warning mark or red. Tests pin all three.
2. **Per-window tab counts** come from `DeskTabs` only for desks past the menu's per-window gate. Every other desk, an older workhorse script included, gets the fallback of Task A5. The cells are decoration; the state words are what counts.
3. **A result and a different notice at once:** both show, the result on the first line and the notice under it, inside the two reserved lines.
4. **windowtool gains `size`,** which sets the window's size, for the 700 by 440 picture. Its header comment says so; every other command still only reads.
5. **The long-folder sample's new desk** (a long name, nine windows) stays in Part B with the pictures it changes.
6. **No art colour in step 1.** Leave `clayArt` out of `LookToken` and its tests; step 3 adds it with the art.
7. **The sidebar keeps the system's look until step 3.** For this one step it sits beside the new ground with today's divider. The pull request says so, and the owner is told before any rollout.
8. **Today's row fields** (`DeskRow.windows`, `tabs`, `second`) stay through step 1; step 2 retires them.

    public static func ratio(_ pair: LookPair, in appearance: LookAppearance) -> Double }
