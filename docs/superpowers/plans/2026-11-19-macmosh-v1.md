# MacMosh v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build MacMosh v1: a menu-bar app on the daily Mac that sets up a spare Mac as a workhorse, shows its state, and gives buttons for desks, screen sharing, restart and restart recovery.

**Architecture:** One Swift package holds the engine (`MacMoshKit`) and the `macmosh` command. A native SwiftUI menu-bar app is a thin face over the same engine. The workhorse gets one bash script (`macmosh-host`) and a login agent, installed over ssh; desks are tmux sessions on a tmux server of their own (socket `macmosh`).

**Tech Stack:** Swift 6 (tools version 6.0, macOS 15 or later), swift-argument-parser 1.8.2, Swift Testing, bash 3.2 and shellcheck for the workhorse script, tmux 3.8, mosh 1.4.0, OpenSSH (the system's), SwiftUI's `MenuBarExtra` for the menu-bar app, GitHub Actions for CI.

**Spec:** [`docs/superpowers/specs/2026-11-18-macmosh-v1-design.md`](../specs/2026-11-18-macmosh-v1-design.md), approved by Shariq on 2026-11-19. Section numbers below ("design 7.6") point into it. Read it before any task.

## Global Constraints

Every task's requirements include these. Values are copied from the design.

- **macOS:** 15 or later on both Macs. The workhorse is Apple silicon. Restart recovery over ssh needs macOS 26 or later on the workhorse (design 5.5, 7.12).
- **Passwords:** nothing in MacMosh ever types, stores or sees a password. A password is typed by the user into ssh, `sudo` or Screen Sharing (design 1, 4).
- **Root:** MacMosh never runs as root on either Mac (design 10).
- **Hands off:** never edit `~/.ssh/config`, `~/.ssh/known_hosts`, shell start-up files or `~/.tmux.conf`. Never touch a tmux session MacMosh didn't create: every tmux call on a workhorse names the socket (`tmux -L macmosh`) (design 4, 7.3).
- **Security settings:** never change FileVault, Remote Login, Screen Sharing or the firewall. Power settings change only in a password tab that shows the exact command first (design 4).
- **Network:** the only network calls are ssh (and mosh) to the user's workhorses and the local `tailscale` command. No telemetry, no account, no update check (design 10).
- **ssh identity:** MacMosh's own key is `~/.ssh/macmosh_ed25519`, type `ed25519`, no passphrase, mode 0600 (design 7.6).
- **Key first:** every command that runs ssh with MacMosh's key checks the key file first (`KeyManager.identityState`). When the `-i` file is missing, ssh only warns and then quietly tries the user's own keys (seen with `ssh -G`), so a missing or unusable key ends the command with the "Your ssh key is locked" message and no ssh call.
- **Host identity:** one pinned host key per workhorse, checked on every address, strict checking always on. A different key means "Can't verify it", and no password prompt is ever offered in that state (design 5.2, 7.6).
- **On the workhorse:** only the six items in design 7.11, all in the user's home folder, all removable. Login agent label: `io.github.shariqh.macmosh.host`.
- **Desk names:** letters, digits, `-` and `_` only (design 7.3). This plan also caps them at 64 characters.
- **Timing:** status check every 30 seconds while the workhorse is reachable (design 7.4). `MOSH_SERVER_NETWORK_TMOUT` is one week, 604800 seconds (design 8.1).
- **Identifiers:** bundle identifier `io.github.shariqh.macmosh`; Homebrew tap `shariqh/tap` (design 11).
- **Name and look:** "MacMosh", with "Mac" never more prominent than "Mosh" in size, colour or typeface. No Apple logo and no drawing of Apple hardware. Credit line, verbatim: "Mac and macOS are trademarks of Apple Inc., registered in the U.S. and other countries and regions." (design 11).
- **Shops:** the app and its guides never link to a shop (design 7.10).
- **The real Macs:** the MacBook Pro is Shariq's live workhorse. Installing MacMosh beside his setup and sitting 1 were agreed on 2026-11-19. Nobody restarts it, changes a power or sleep setting, logs it out, or touches its default tmux server. Tests never touch `~/.macmosh`, the `macmosh` socket or the default tmux socket (design 7.13, 7.14, 9).
- **Outward-facing steps:** a release, the Homebrew tap and any post are each asked of Shariq first (design 11).
- **Writing for people** (README, guides, runbooks, issues, PR descriptions): numbered steps with a fallback if something goes wrong; plain-English names, each tool explained the first time; a "which one do I use?" table where there are several ways; short prose. Run the unslop pass on each.
- **Build log:** every task adds its entry to `docs/build-log.md`, with the time read from `date` (design goal 9).

## Review Focus

Five conditions the design implies but doesn't spell out, most likely first. Each has a test in the task that owns the code.

1. **Odd characters in a desk's folder or startup command** (spaces, quotes, `$`, non-ASCII). The desk opens in exactly that folder and the command is typed as written; nothing is expanded on the daily Mac or by ssh's remote shell. Tests: Task 3 (`folderWithSpacesQuotesAndDollar`, `startupCommandIsTypedLiterally`), Task 14 (`remoteStringSurvivesTheRemoteShell`).
2. **A status report that is cut off, noisy or from another version** (a shell start-up file that prints text, a dropped connection, an old script). The app never shows Ready from a partial report. Tests: Task 9 (`skipsNoiseBeforeTheHeader`, `missingEndIsTruncated`, `unsupportedProtocolIsReported`).
3. **A different host key at the workhorse's address** (another machine took the home address, or an attacker). The state is "Can't verify it" and `unlock` refuses to run. Tests: Task 10 (`anyChangedKeyMeansCantVerify`), Task 17 (`unlockRefusesWhenTheKeyDiffers`).
4. **An ssh that hangs** (sleeping Mac, captive portal, packet loss). Every check ends within its time limit and the menu still draws. Tests: Task 6 (`killsAtTimeout`), Task 11 (`everyProbeHasATimeLimit`), Task 19 (`rendersWithinTheBudgetWhenNothingAnswers`).
5. **Removal that takes more than MacMosh's own things.** Removing MacMosh deletes one line of `authorized_keys`, never the file, and refuses an empty key. Tests: Task 3 (`uninstallRemovesOnlyMacMoshThings`, `uninstallRefusesAShortOrEmptyKey`).

## Decisions this plan makes

Design section 14 left these to the builder. They are decided here so every task agrees.

| Left open in the design | Decision | Why |
|---|---|---|
| Package layout, Xcode project | One Swift package at the repo root: library `MacMoshKit`, executable `macmosh`, and in phase 3 an executable `MacMoshApp` that a script wraps into `MacMosh.app`. No Xcode project file | Everything builds and tests with `swift build` and `swift test`, on the Mac and in CI. Task 26 proves the app bundle works this way before anything depends on it; if it doesn't, that task stops and asks |
| Command-line parsing | swift-argument-parser, `from: "1.8.2"` | Apple's own package; saves a hand-written parser |
| Test framework | Swift Testing (`import Testing`) | Ships with the Swift 6 toolchain on both CI images |
| Format of `macmosh-host status` | Tab-separated lines; first line `macmosh-host<TAB>1<TAB><script version>`; last line `end` (see "Shared interfaces") | Easy to write safely in bash and to parse strictly; the last line shows a cut-off report |
| The workhorse script's shell | `#!/bin/bash`, bash 3.2 features only, clean under shellcheck | bash 3.2.57 is what macOS ships at `/bin/bash`; shellcheck can't check zsh |
| How the script reaches a workhorse | Its text is compiled into the `macmosh` binary; `prepare` pipes it over ssh | One file to install, and the binary works wherever it is copied |
| Files under `~/.macmosh/`, login agent keys | As design 7.11. The script writes the login agent's file itself: `RunAtLoad` true, `LimitLoadToSessionType` `Aqua`, `ProgramArguments` `/bin/zsh -lc 'exec "<script path>" start'`, no `KeepAlive` | The keys proven by the hand-built setup (design 8.2) |
| Reusing ssh connections | None in v1: one fresh ssh per check, `ConnectTimeout=5` | A kept-open connection would leave something running on the workhorse between checks (design 7.4) and can go stale |
| The "home address reachable from here" light | One more ssh call per check, to the home address, when the report came over the main address | Design 7.9 wants the light tested the same way at home and away, and design 10 allows no network call other than ssh |
| Check interval and back-off | 30 s while reachable. While unreachable: 30, 60, 120, then 300 s. At once when the menu opens | Design 7.4 |
| "Focus the tab that already has this desk" | Not in v1. A second click opens a second tab; the menu shows how many tabs are attached | Both terminals would need per-tab lookups; tmux and mosh handle two clients fine |
| mosh typing prediction | `adaptive` (mosh's default); a per-workhorse setting offers `always`, `never`, `experimental` | Design 14 |
| A refused key while opening a desk | `connect` never falls back to a password prompt: its ssh runs with `PasswordAuthentication=no` and `KbdInteractiveAuthentication=no` | The only password prompts are the ones the design names: pairing, unlock, and `sudo` in a password tab |
| The first menu | The native app's `MenuBarExtra`, drawn from `MenuModel`. Plain menu items first; a submenu per desk comes with Task 27 | Shariq ruled out a third-party menu-bar tool on 2026-11-19 |
| Icon and wording | Task 31, within the trademark rules | Design 14 |

## Facts checked for this plan

Checked on 2026-11-19. **Seen** means observed on the MacBook Pro (macOS 27.3, OpenSSH 10.5p1, tmux 3.8, mosh 1.4.0) with read-only commands or on a throwaway tmux socket. **Vendor** means the vendor's own page or manual.

- **Seen.** ssh prints these lines, which Task 8 tells apart:
  - refused sign-in: `<user>@<host>: Permission denied (publickey,password,keyboard-interactive).` (exit 255). The list in brackets is the sign-in methods the server offers;
  - changed key, with strict checking: `@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @`, then `Host key for <alias> has changed and you have requested strict checking.` and `Host key verification failed.`;
  - no key on file: `No ED25519 host key is known for <alias> and you have requested strict checking.` and `Host key verification failed.`;
  - `ssh: connect to host <h> port 22: Operation timed out`, `ssh: connect to host <h> port 22: Connection refused`, `ssh: Could not resolve hostname <h>: nodename nor servname provided, or not known`.
- **Seen**, while building Task 8. ssh's messages depend on its log level: at `LogLevel=QUIET` it prints nothing for a refusal or a changed key, and at `ERROR` a changed key shows only `Host key verification failed.`. A level set on the command line wins over the user's ssh config, and `INFO` is the default. With a missing `-i` file ssh prints `Warning: Identity file <path> not accessible: No such file or directory.` and falls back to the default key files. ssh accepts `--` before the destination.
- **Seen.** `-o HostKeyAlias=<alias>` makes ssh look the key up under the alias whatever address is used, so one pinned line covers every address of a workhorse. **Vendor** (`man ssh_config`): "Values may optionally be enclosed in double quotes (") in order to represent arguments containing spaces", which the path under `Application Support` needs.
- **Seen.** ssh accepted `-o 'UserKnownHostsFile="<a path with a space>"'` and found the pinned key, both as one argument and after Perl's `shellwords` had split the whole option string. The same path without the double quotes failed with `Host key verification failed.`
- **Seen.** mosh 1.4.0 splits the `--ssh` value with Perl's `shellwords`, and pastes the `--server` value into the remote command line as written, so `--server='NAME=value mosh-server'` sets a variable for the server.
- **Seen**, on a throwaway socket: a tmux server started with `start-server` and `set -s exit-empty off` stays up with no sessions. `tmux run-shell '<command>'` runs the command inside the server and passes its output and exit code back to the caller. The keychain check run that way printed `ok`. `-t '=name'` matches a session name exactly.
- **Seen.** Output shapes on the MacBook Pro: `pmset -g batt` prints `Now drawing from 'AC Power'` then ` -InternalBattery-0 (id=…)<TAB>76%; AC attached; not charging present: true`. `pmset -g custom` has an `AC Power:` section with lines such as ` sleep                0` and ` womp                 1` (no `autorestart` line on a laptop). `fdesetup status` prints `FileVault is On.`. `fdesetup supportsauthrestart` prints `true` without root. `socketfilterfw --getglobalstate` prints `Firewall is disabled. (State = 0)`. `scutil --nc list` marks a running VPN with `(Connected)`, and Tailscale's own line contains `io.tailscale.ipn`. With Screen Sharing on, `launchctl print-disabled system` has the line `"com.apple.screensharing" => enabled` (seen on both Macs, without root; the line for a Mac with it off has not been seen).
- **Seen.** `tailscale status --json` has `BackendState` (`Running` when on) and a `Peer` map whose values have `HostName`, `DNSName`, `OS` (`macOS`, `linux`) and `Online`. The command is at `/Applications/Tailscale.app/Contents/MacOS/Tailscale` and, where the user installed it, on `PATH`.
- **Vendor.** `fdesetup authrestart`: "If FileVault is enabled on the current volume, it restarts the system, bypassing the initial unlock", and "The command may not work on all systems" (`man fdesetup`). The system's `ssh-copy-id` refuses a second `-i` and passes each `-o` value on with its quoting intact (read in the script). tmux looks for the user's settings "at ~/.tmux.conf or $XDG_CONFIG_HOME/tmux/tmux.conf" (`man tmux`).
- **Vendor.** `launchctl bootstrap gui/<uid> <plist>` loads a login agent, `launchctl bootout gui/<uid>/<label>` removes it, and `launchctl kickstart gui/<uid>/<label>` runs it now (`man launchctl`). Whether these work from an ssh session is sitting 1, item 1.
- **Vendor.** swift-argument-parser 1.8.2 (2026-06-04) is the latest release, with tools version 6.0. GitHub's Apple-silicon runner images are `macos-15` and `macos-26`. `actions/checkout` is at v7.0.1 (commit `3d3c42e5aac5ba805825da76410c181273ba90b1`).
- **Reports, to confirm in sitting 2.** `stat -f %Su /dev/console` prints `root` when nobody is logged in at the screen. The locked screen's ssh offers no `publickey` method (design 7.6 says it "can't offer keys at all").

The command (`Sources/macmosh`) stays thin: it parses arguments and calls MacMoshKit. Anything worth a test lives in MacMoshKit.

`Tests/MacMoshKitTests/Support/` holds the stand-ins the tests name (`FakeRunner`, `FakeInteractive`, `ScriptedInteraction`, `FixedHints`) and `Samples.swift`, with sample values such as `Workhorse.sample(…)`, `Paths.test`, `temporaryPaths()`, `HostStatus.sampleReady`, `Hints.allFine`, `fixture(_:)` and `repoRoot()`. (`#filePath` as a default argument names the caller's file, so the helpers use their own.) The two test targets can't see each other's support files: `MacMoshHostTests` has its own `Support/HostHarness.swift` and uses only MacMoshKit's public API.

## Shared interfaces

Tasks refer to these by name. A task's own Interfaces block adds what only it defines.

### The workhorse script

`host/macmosh-host <subcommand>`. It reads two environment variables: `MACMOSH_HOME` (default `$HOME/.macmosh`) and `MACMOSH_SOCKET` (default `macmosh`). It adds `/opt/homebrew/bin:/usr/local/bin` to the **end** of `PATH`, so tests can put stand-in tools first.

| Subcommand | Does | Exit codes |
|---|---|---|
| `version` | Prints the script version, `0.1.0` | 0 |
| `start` | Starts the desk server if it is down, then recreates the desks marked reopen. Run by the login agent | 0 |
| `status` | Prints the status report | 0 |
| `attach [--cc] [--dry-run] <desk>` | Attaches to the desk, creating it from its definition if needed. Never starts the server itself: if it is down, asks macOS to run the login agent and waits up to 5 s. `--cc` is iTerm2's Tabs mode. `--dry-run` stops before attaching and prints `ok` | 3 nobody logged in; 4 no such desk; 5 server didn't start |
| `desk-new <name> <folder> [--reopen] [--keep] [--command <text>]` | Adds a definition and creates the session | 3, 5 as for `attach`; 6 bad name, folder or command; 7 already exists |
| `desk-remove <name> [--kill]` | Removes the definition; closes the session only with `--kill` | 4 |
| `window-new <desk>` | Adds a window to the desk | 3, 4, 5 |
| `folders <folder>` | Prints the names of the folders inside it, one per line, sorted, without hidden ones. A leading `~` means the home folder | 6 |
| `install-agent` | Writes the login agent's file and loads it | 0, or `launchctl`'s code |
| `restart-server --yes` | Closes every desk and starts the server again through the login agent | 2 without `--yes` |
| `uninstall --key <base64 key>` | Unloads and deletes the login agent, deletes `MACMOSH_HOME`, removes the one matching line from `~/.ssh/authorized_keys`. Leaves the server and open desks running | 2 if the key is missing or shorter than 60 characters |

Usage errors exit 2. Every tmux call goes through one function, `mm_tmux() { command tmux -L "$MACMOSH_SOCKET" "$@"; }`, except the two lines that hand the terminal over, which are `exec tmux -L "$MACMOSH_SOCKET" …` because bash can't `exec` a function.

**Only `start` starts the desk server.** tmux starts a server for any command that needs one, and a server started from an ssh login can't read the keychain (design 7.3). So `attach`, `desk-new` and `window-new` first call one function, `mm_require_server`: if the server is down and nobody is logged in at the screen, exit 3; if somebody is, ask macOS to run the login agent, wait up to 5 seconds, and exit 5 if the server still isn't up.

### Swift types used across tasks

// Model
public struct DeskName: Hashable, Codable, Sendable { public let value: String; public init?(_ raw: String) }
public enum ConnectionMode: String, Codable, Sendable, CaseIterable { case mosh, tabs, ssh }

public struct Workhorse: Codable, Sendable, Identifiable, Equatable {
    public var id: String                 // slug: a-z, 0-9, "-"; the ssh host-key alias is "macmosh-<id>"
    public var name: String               // shown in the menu
    public var user: String
    public var mainAddress: String        // what the user chose, normally the Tailscale name
    public var homeAddress: String?       // from the last status report
    public var homePrefix: Int?
    public var localName: String?         // "name.local"
    public var hostKey: String            // "ssh-ed25519 AAAA…", the pinned key
    public var paired: Bool
    public var mode: ConnectionMode       // default .mosh
    public var prediction: Prediction     // default .adaptive
    public var projectsFolder: String?
    public var identityFile: String?      // nil means ~/.ssh/macmosh_ed25519
    public var osVersion: String?; public var arch: String?
    public var lastSeen: Date?; public var lastKeyAccepted: Date?
    public var powerChanges: [String]     // pmset commands run through MacMosh, for "Remove"
}
public struct Paths: Sendable {
    public var supportDir: URL            // ~/Library/Application Support/MacMosh
    public var sshDir: URL                // ~/.ssh
    public init(supportDir: URL, sshDir: URL)
    public static func standard() -> Paths
    public var workhorsesFile: URL { get }    // supportDir/workhorses.json
    public var settingsFile: URL { get }      // supportDir/settings.json
    public var knownHostsFile: URL { get }    // supportDir/known_hosts
    public var defaultIdentity: URL { get }   // sshDir/macmosh_ed25519
}

// Status
public enum SetupProblem: String, Sendable, Codable {
    case notPaired, identityUnusable, hostScriptMissing, hostScriptOutdated, unreadableReport, deskServerDown
}
public enum UnreachableReason: String, Sendable, Codable {
    case tailscaleOff, noNetwork, otherVPN, awayAndOffline, nothingAnswers
}
public enum WorkhorseState: Sendable, Equatable {
    case ready(signIns: Bool)             // false is "Ready, sign-ins off"

`WorkhorseState` has one case the design's table doesn't: `notSetUp`. It covers a workhorse that answers but isn't finished (not paired, script missing or old, a report that couldn't be read, desk server down) and the design's "your ssh key is locked" message (`identityUnusable`).

## Every task

These apply to every task and are not repeated in the steps.

1. Work on a branch named `task/<number>-<short-name>`, never on `main`.
2. Write the test first, watch it fail, then write the code.

```swift
final class HostHarness {
    let home: URL                     // a fresh temporary folder, used as HOME
    let socket: String                // "macmosh-test-" + 8 random hex characters
    init() throws
    var scriptVersion: String { get } // read from the script's MACMOSH_HOST_VERSION line
    func stub(_ tool: String, script: String) throws      // an executable stand-in placed first on PATH
    func run(_ arguments: [String], stdin: String? = nil) -> (exitCode: Int32, stdout: String, stderr: String)
    func tmux(_ arguments: [String]) -> (exitCode: Int32, stdout: String)   // always with -L socket
    func installScriptInHome() throws // copies the script to <home>/.macmosh/macmosh-host
    func shell(_ commandLine: String) -> (exitCode: Int32, stdout: String, stderr: String)   // /bin/sh -c, same environment as run
    func cleanUp()                    // tmux -L socket kill-server, then removes home
}
```

`run` starts `host/macmosh-host` with `HOME=<home>`, `MACMOSH_SOCKET=<socket>`, `PATH=<stub folder>:<the test's PATH>` and with `TMUX` removed from the environment. `init` fails if the socket name doesn't start with `macmosh-test-`. The same file has `func waitFor(seconds: Double, _ condition: () -> Bool) throws`, which checks every tenth of a second and throws when the time runs out.

A new harness starts with two stand-ins, so that no test depends on, or reaches, the Mac it runs on: `launchctl` (appends its arguments to `<home>/launchctl.log`, prints nothing, exits 1) and `stat` (prints `tester` for `-f %Su /dev/console`, and passes anything else to `/usr/bin/stat`). The script calls both by bare name. After sitting 1 the real login agent exists on the MacBook Pro, and a test that reached the real `launchctl` would start the real desk server.

How the script finds each line of the report:

| Record | Command | Mapping |
|---|---|---|
| `os` | `sw_vers -productVersion`, `uname -m` | |
| `console` | `stat -f %Su /dev/console` | `root`, `loginwindow`, `_mbsetupuser` or nothing give an empty field |
| `server` | `mm_tmux list-sessions` | exit 0 is `up` |
| `signins` | `mm_tmux run-shell 'security show-keychain-info "$HOME/Library/Keychains/login.keychain-db" >/dev/null 2>&1 && echo ok \|\| echo off'` | the word printed; `unknown` when the server is down |
| `filevault` | `fdesetup status` | begins `FileVault is On` or `FileVault is Off` |
| `authrestart` | `fdesetup supportsauthrestart` | `true` is `yes`, `false` is `no` |
| `power` | `pmset -g custom`, lines after `AC Power:` | the first whole number after the setting's name |
| `battery` | `pmset -g batt` | `InternalBattery` present; `'AC Power'` on the first line; the number before `%` |
| `home` | `route -n get default` (its `interface:` line), `ipconfig getifaddr <if>`, `ipconfig getoption <if> subnet_mask`, `scutil --get LocalHostName` | the mask becomes a prefix length; the name gets `.local`. When the default route's interface is a `utun` one, or its address is in `100.64.0.0/10` (Tailscale's range), use the first of `en0` to `en9` that has an IPv4 address instead |
| `firewall` | `/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` | contains `enabled` or `disabled` |
| `screensharing` | `launchctl print-disabled system` | the line `"com.apple.screensharing" => enabled` is `on`; `=> disabled` is `off`; no such line is `unknown` |
| `tool` | `command -v`, `tmux -V`, `mosh-server --version` | |
| `agent` | the login agent's file exists | |
| `desk`, `window` | `mm_tmux list-sessions -F`, `mm_tmux list-windows -t "=<desk>:" -F` | |

When the server is down, `start` writes `$MACMOSH_HOME/tmux.conf` with exactly these lines, then runs `mm_tmux -f "$MACMOSH_HOME/tmux.conf" start-server`:

```
# MacMosh defaults. Your own tmux settings are loaded next, so your settings win.
set -g mouse on
set -g history-limit 50000
source-file -q "<your settings file>"
set -s exit-empty off
```

`<your settings file>` is `$HOME/.tmux.conf` when that exists, otherwise `${XDG_CONFIG_HOME:-$HOME/.config}/tmux/tmux.conf`: the two places tmux itself looks, which `-f` would otherwise skip.

Every subcommand appends one line to `$MACMOSH_HOME/host.log`: an ISO 8601 time, the subcommand, and the result.

`ProcessRunner.run` finds a bare name such as `ssh` on `PATH`; adds `environment` on top of the process's own; reads stdout and stderr while the child runs; and at `timeout` sends SIGTERM, then SIGKILL two seconds later, returning `timedOut: true` and `exitCode: -1`. `ProcessRunner.runAttached` gives the child the terminal (the parent's own standard input, output and error) and waits. While the child runs, the parent ignores Ctrl-C (SIGINT), so the key reaches ssh or mosh and `macmosh` is still there afterwards to say what happened. It returns the child's exit code, or 128 plus the signal number.

`hostKeyOptions` returns, in this order: `-o HostKeyAlias=macmosh-<id>`, `-o UserKnownHostsFile="<paths.knownHostsFile>"` (the double quotes are part of the value), `-o GlobalKnownHostsFile=/dev/null`, `-o StrictHostKeyChecking=yes`, `-o UpdateHostKeys=no`. `options` returns those, then `-o IdentitiesOnly=yes`, `-i <identity>`, and `-o IdentityAgent=none` only when `identityFile` is nil. With `batch: true` it adds `-o BatchMode=yes -o ConnectTimeout=5 -o LogLevel=INFO`. The log level is there because `classify` reads ssh's messages, and a quieter level in the user's ssh config would hide them. `sshStringForMosh` is `options(batch: false)` plus `noPasswordOptions`.

Each `-o` value is one argument. The key file's value keeps its double quotes inside that argument, and ssh's own option parser removes them. `sshStringForMosh` wraps every argument with `ShellQuote.posix`, so mosh's `shellwords` gives back the same arguments.

`argv` returns `["ssh"] + options + extraOptions + (tty ? ["-t"] : []) + ["--", "<user>@<address>"] + remote`. The `--` means a destination can never be read as an option. An empty `remote` gives an interactive login.

`classify` checks in this order and returns the first match:

| Order | Sign | Outcome |
|---|---|---|
| 1 | stderr contains `REMOTE HOST IDENTIFICATION HAS CHANGED` or `has changed and you have requested strict checking` | `.hostKeyChanged` |
| 2 | stderr contains `host key is known for` | `.hostKeyUnknown` |
| 2a | stderr contains `Host key verification failed` and neither phrase above | `.hostKeyChanged`, the cautious reading |
| 3 | `timedOut` is true, or stderr contains `Operation timed out` or `Connection timed out` | `.timedOut` |
| 4 | stderr contains `Connection refused` | `.refused` |
| 5 | stderr contains `Could not resolve hostname` | `.unresolved` |
| 6 | stderr contains `no such identity`, `UNPROTECTED PRIVATE KEY FILE`, `bad permissions` or `incorrect passphrase`, or both `Identity file` and `not accessible` | `.identityUnusable` |
| 7 | stderr contains `Permission denied (` | `.authDenied`, with the comma-separated names inside the brackets |
| 8 | exit code 0 | `.ok` |
| 9 | exit code 255 | `.unreachable`, with the last line of stderr |
| 10 | any other exit code | `.remoteFailed` |

Rules:

- `scan` runs `ssh-keyscan -T 5 -t ed25519 <address>` and returns the key type and key from the first line that isn't a comment.
- `ensureIdentity` runs `ssh-keygen -q -t ed25519 -N "" -C "macmosh@<this Mac's name>" -f <path>`.
- `add` takes `user@address`. It refuses a target with no user, with a space, or beginning with `-`. It scans, makes the id from the name (or from the address's first label when no name is given), and saves the workhorse with `paired == false`. For an address that is already saved, it changes nothing when the scanned key is the saved one and throws `.keyDiffers` when it isn't. It never replaces a pinned key.
- `pair` accepts a saved workhorse or a `user@address` (which it adds first). It begins by calling `ensureIdentity()`, and says `Created MacMosh's own ssh key at <path>.` when that made a new key. Then it says, in this order:
  1. `This installs MacMosh's own ssh key on <user@address>, so MacMosh can check on that Mac without a password.`
  2. `Its key fingerprint is: <fingerprint>`
  3. `At the workhorse, run this and compare: ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`
  4. It asks `Type yes if they match: ` unless `confirmedFingerprint` equals the fingerprint. Any other answer throws `.declined` and nothing is copied.
  5. `Next, ssh asks for the workhorse's password. You are typing into ssh; MacMosh can't see it.`
  6. It hands the terminal to `copyIDArgv`: `ssh-copy-id -i <identity>.pub`, then `SSHInvocation.hostKeyOptions`, then the target. It doesn't add `options`: those contain a second `-i`, which `ssh-copy-id` refuses.
  7. It runs a batch probe with the remote command `scutil --get ComputerName`. Anything but `.ok` throws `.keyNotAccepted`.
  8. It sets `paired = true` and `lastKeyAccepted = now()`, replaces a name that was taken from the address with the computer name, saves, and says `Paired. Next: macmosh prepare <id> --fix`.
- `macmosh pair` with no argument lists the Tailscale devices whose `OS` is `macOS`, numbered, and lets the user pick one or type an address; it asks for the user name, offering the current one.
- On an error the command says what it tried, what came back and the one thing to do next (design 5.3), and ends with `finish`.

`unlock`, step by step:

1. Check the state. `.cantVerify`: say the Can't-verify hint and stop, exit 1, without running ssh. Ready or Waiting for login: say `The disk is already unlocked.`, exit 0. A workhorse whose saved version and chip fail `canUnlockOverSSH`: say `This Mac can't be unlocked over the network: that needs Apple silicon and macOS 26 or later. Unlock it at the Mac.`, exit 1. `.cantReach`: say the hint, exit 1.
2. `.locked`: say `You are about to type the Mac's password into ssh. MacMosh can't see it.` and `When the unlock works, the connection closes by itself.` (design 7.8).
3. Hand the terminal to `unlockArgv`: ssh with the pinned-key options (not batch), plus `-o PreferredAuthentications=password,keyboard-interactive -o PubkeyAuthentication=no`, to `<user>@<the home or local address that answered>`, with no remote command.
4. Check again every 5 seconds, for up to 2 minutes, until the state is no longer Locked or Can't reach it, and say the new headline. For Waiting for login add `Next: press Log in…, or run: macmosh screen <id>`.

`restart`, step by step:

1. Check the state; it must be Ready or Waiting for login. Say `These desks will close: <names>.` or `No desks are open.`
2. Choose the command, and say what will happen:
   - The report says `filevault on` and `authrestart yes`, and `full` is false: `sudo fdesetup authrestart`, which needs FileVault on (`man fdesetup`). Say `The Mac restarts with its disk already unlocked.`
   - FileVault on, otherwise (`--full`, or no authrestart support): `sudo shutdown -r now`. Say `After this restart the disk will be locked. You unlock it with Unlock disk…` (or `…at the Mac.` when `canUnlockOverSSH` is false).
   - FileVault off: `sudo shutdown -r now`. Say `FileVault is off, so the Mac comes back to the login window by itself.`
3. Ask `Type restart to go ahead: `. Any other answer runs nothing, exit 1.
4. Say `ssh asks for the Mac's password, for sudo. You are typing into ssh; MacMosh can't see it.` For `authrestart` add `Then fdesetup asks for a user name and password that can unlock the disk.` Then hand the terminal to `restartArgv` (ssh with `-t` and the command).

Both commands end with `ui.finish`, so a refusal or a failure leaves the tab open with the reason.

`screenSharingURL` is `vnc://<user>@<address>`, with the address that answered the check. `macmosh screen <workhorse>` opens it with `open`.

    /// How long to wait before the next background check.
    /// `missesInARow` counts the checks in a row in which some workhorse was Can't reach it.
    public static func delay(missesInARow: Int) -> Duration        // 0 or 1: 30 s; 2: 60 s; 3: 120 s; 4 or more: 300 s
    public static func isMiss(_ gathered: [Gathered]) -> Bool      // any .checked result whose state is .cantReach
}
public protocol TabOpening: Sendable {                             // TabOpener conforms; tests use a stand-in
    func open(_ command: TabCommand, title: String) async throws -> String?
}
public struct MenuActionRunner: Sendable {
    public init(macmoshPath: String, tabs: TabOpening, runner: CommandRunner)
    /// Does what a menu item asks. Returns a sentence to show the user when there is one
    /// (a fallback notice from the tab opener, or why the action could not run).
    public func perform(_ action: MenuAction, title: String) async -> String?
    public static func tabTitle(for arguments: [String]) -> String  // the desk for "connect", otherwise the subcommand
}
extension MenuRefresher {
    public func runInBackground(sleep: @escaping @Sendable (Duration) async -> Void) async   // refresh, wait PollSchedule's delay, repeat
    public var notice: String? { get }      // the last sentence from an action, shown as the menu's first line until the next action
}

What the task decides:

- **Buttons.** In `MenuContent`, an item whose action is `.none` stays a line of text. Any other item is a `Button` that calls `MenuActionRunner.perform` and then `refresher.refresh()`. Indent is shown with leading spaces, three per level, as in the design's sketch (design 5.1). There are no submenus: a desk's line already names its windows, and `New window in <desk>` sits under it.
- **`.tab`.** Builds `TabCommand(macmoshPath:arguments:)` and opens it through `TabOpening`, with `tabTitle(for:)` as the title. If `TabCommand` refuses the path (the app is in a folder whose path has a space or another character it doesn't allow), nothing is opened and the sentence is: `MacMosh can't open terminal tabs from where it is now. Move it to the Applications folder and open it again.`
- **`.run`.** Runs the bundled command with those arguments through `CommandRunner`, with a 30-second limit, and returns nothing on exit code 0. On any other result the sentence is the last line the command printed to stderr, or `That didn't work (exit code <n>).` when it printed nothing.
- **`.refresh`.** Nothing to run; the refresh that follows every action does it.
- **The command's path.** `Bundle.main.bundleURL` plus `Contents/Helpers/macmosh`.
- **Background checks.** `MacMoshApp` starts `runInBackground` once at launch, in place of Task 26's fixed 30-second timer. After each refresh it waits `PollSchedule.delay(missesInARow:)`. A refresh in which no workhorse is Can't reach it sets the count back to 0.
- **When the menu opens.** `MenuContent` calls `refresher.refresh()` in `onAppear`. Whether macOS runs `onAppear` each time a `MenuBarExtra` menu opens is checked on the Air in Task 20; if it doesn't, `Check now` and the schedule cover it, and the build log says so.
- **One check at a time.** Two refreshes never run at once. A refresh asked for while one is running is remembered, and exactly one more runs straight after it, so the check that follows an action is never lost. (Task 26's `MenuRefresher` dropped the second request; this task changes that.)
