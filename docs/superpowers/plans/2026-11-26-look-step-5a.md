# The look, step 5a: the M app icon: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give MacMosh the M icon the owner chose, light and dark, built by `scripts/build-app.sh` from an Icon Composer document drawn by a script in the repository. The icon must be shown on CI's macOS 15 and 26 runners, in light and in dark, before the pull request may merge.

**Architecture:** `IconArt` in MacMoshKit holds the M's thirteen cells, the grid and the icon's colours under test. A Swift script, compiled together with that one file, draws three committed pictures: the light and dark layers of `App/AppIcon.icon` and a solid 16-pixel M. `build-app.sh` compiles the document with `xcrun actool` (using Xcode 26 or newer, which it finds itself when the selected one is older) into `Assets.car` and `AppIcon.icns`. It swaps the 16-pixel picture in the `.icns`, copies both into `Contents/Resources` and signs afterwards, as today. A new workflow draws the built app's icon as the system gives it. The existing window jobs already photograph the Remove confirmation, which shows the icon, in light and in dark.

**Tech Stack:** Swift 6 package, macOS 15+, Swift Testing; CoreGraphics and ImageIO in the drawing script; AppKit in one CI tool; Xcode's `actool`, macOS's `iconutil`, `assetutil` and `sips`; bash and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-25-look-design.md`: step 5a is section 14 item 5 (5a only), with section 8 whole, section 13, section 15 and the sources of section 16 it cites. The picture the owner chose is `docs/superpowers/specs/look-2026-11-25/icon-m-light-and-dark.png`. Issue #175, part of #34.

## What the trial settled (this Mac, macOS 27.3, Xcode 27.2, 2026-11-25; scratch folders only)

- **The document shape (T1).** The `icon.json` of Task 2 has two full-bleed 1024 by 1024 layers swapped by `hidden-specializations` and a fill per appearance. `actool` exits 0 with no warning. `assetutil --info` lists an `IconImageStack` for `NSAppearanceNameAqua`, `NSAppearanceNameDarkAqua` and `ISAppearanceTintable`, and the images `AppIcon_Assets\/m-light` and `AppIcon_Assets\/m-dark`. The partial plist holds `CFBundleIconFile` and `CFBundleIconName`, both `AppIcon`. With `--standalone-icon-behavior all`, `AppIcon.icns` holds ten pictures, `icon_16x16.png` to `icon_512x512@2x.png`. That `.icns` is the light layer with the system's mask, margin and shading.
- **No art for one size inside the document (T2).** No key for it was found in Apple's pages. An `AppIcon.appiconset` given to the same `actool` call, with its own 16-pixel picture, was ignored without a warning: the `.icns`'s 16-pixel picture was the document's. Apple says an Icon Composer file "replaces any existing icon asset catalog".
- **The swap works (T3, T4).** `iconutil -c iconset` of the `.icns`, then a 16 by 16 PNG (opaque or with transparency) copied over `icon_16x16.png`, then `iconutil -c icns`: exit 0, and the picture read back is the new one. The swap reaches the loose `.icns` only, never `Assets.car`, whose smallest icon picture is 32 pixels (16 points at 2x).
- **Failures (T5, T6, T7).** A missing layer picture or a broken `icon.json` makes `actool` exit 1 with "error: Failed to create a catalog from the Icon Studio document". A document path that does not exist makes it exit 0 with only an empty partial plist (`<dict/>`).
- **`actool` takes relative paths from somewhere other than the shell's folder** (a run from one folder wrote into another's `out`). Every `actool` path in the script is absolute or starts at the repository root after the script's own `cd`.

### Task 1: IconArt: the M's cells, the grid and the colours

**Files:**
- Create: `Sources/MacMoshKit/Look/IconArt.swift` (no `import` line at all: the drawing script compiles this file with itself)

**Interfaces** (produces; step 6 reuses `IconArt.mCells` for the menu-bar mark):
```swift
public struct IconCell: Hashable, Sendable { public let row: Int; public let column: Int
    public init(row: Int, column: Int) }                       // counted from 0 at the top left
public enum IconAppearance: Sendable, CaseIterable { case light, dark }
public struct IconStop: Equatable, Sendable { public let location: Double; public let rgb: UInt32
    public init(_ location: Double, _ rgb: UInt32) }
public enum IconArt {
    public static let gridSize = 5
    public static let mCells: [IconCell]                       // the 13, row by row, left to right
    public static func isLit(_ cell: IconCell) -> Bool
    public static let canvas = 1024, inset = 102, tile = 140, gap = 30, tileRadius = 32
    public static func tileOrigin(_ cell: IconCell) -> (x: Int, y: Int)   // top-left corner, y down
    public static func ground(_ a: IconAppearance) -> [IconStop]  // top to bottom over the whole canvas
    public static func lit(_ a: IconAppearance) -> [IconStop]     // top to bottom from y = inset to canvas - inset, seen through the M's tiles
    public static func unlit(_ a: IconAppearance) -> [IconStop]   // top to bottom inside each other tile
    public static let small = 16, smallBodyOrigin = 1, smallBodySize = 14, smallBodyRadius = 3
    public static let smallMOrigin = 3, smallCell = 2                // the M fills 10 by 10 pixels at (3, 3), no gaps
    public static func smallGround(_ a: IconAppearance) -> UInt32
    public static func smallM(_ a: IconAppearance) -> [IconStop]
}
```
The geometry is this plan's, measured from `icon-m-light-and-dark.png`, because the design gives the colours and cells but no sizes. The tiles inset by a tenth of the side, and the M's grid is 820 of 1024. Design 8.1 gives the dark lit colours in order but no positions, so the plan spaces them evenly.

It must be `main.swift`: with two files, only a file of that name may hold top-level code (the Swift book, quoted in the pull request). It imports CoreGraphics and ImageIO (and Foundation only for paths if needed; never AppKit). It refuses any other number of arguments (exit 2, usage line) and a folder without `App/AppIcon.icon/icon.json` (exit 1). It writes the three PNGs in sRGB with `CGImageDestinationCreateWithURL` and type `"public.png"`, and prints `draw-icon: wrote <path> (<w> by <h>)` for each.

What it draws, all from `IconArt` (CoreGraphics' origin is bottom left; the script flips the context once so `tileOrigin` and rows read from the top):
- `m-light.png` and `m-dark.png`, 1024 by 1024, opaque, square, with no mask: Apple says "Don’t export the canvas mask because the system applies that automatically to ensure a perfect crop." First `ground(a)` from top to bottom over the canvas. Then each of the twelve other tiles: a rounded rectangle at `tileOrigin`, `tile` square, `tileRadius` corners, clipped, with `unlit(a)` from that tile's top to its bottom. Then the M: clip to the union of the thirteen tiles' rounded rectangles and draw `lit(a)` once from `y = inset` to `y = canvas - inset`. No shadow, glow, stroke or highlight.
- `App/AppIcon-16.png`, 16 by 16, transparent outside the body. The body is a rounded rectangle at (1, 1), 14 square, corner 3, filled `smallGround(.light)`. Then each M cell is a 2 by 2 square at (`3 + 2 * column`, `3 + 2 * row`) in `smallM(.light)`, drawn with antialiasing off, so the M is solid and sits on whole pixels. Only the light one is written: the `.icns` holds one appearance (see the open points).

### Task 3: build-app.sh compiles the icon, and the two Info.plist keys

**Interfaces:** the keys live in `App/Info.plist`, which `AppBundleTests` reads. The script does not write them: it checks that `actool`'s partial plist names the same `AppIcon`.

The block, in this order (the body is the builder's; every message starts `build-app.sh: FAILED:`, and the build stops):
1. **Pick the Xcode.** Read the selected one's version from `xcodebuild -version` (first line, `Xcode 16.4`). At 26 or newer, use it as it is. Otherwise take the newest `/Applications/Xcode*.app` whose `Contents/version.plist` gives `CFBundleShortVersionString` 26 or newer (`plutil -extract … raw`), and run `actool` with `DEVELOPER_DIR=<that app>/Contents/Developer`. xcrun's manual: "When DEVELOPER_DIR is set, its value will be used instead of the system-wide active developer directory." Print `build-app.sh: actool from Xcode <version> (<path>, or "the selected Xcode")`. None: `no Xcode 26 or newer found (the selected one is <version or "none">); actool from Xcode 26 or newer compiles App/AppIcon.icon. Install one, or select it with xcode-select.` `/bin/bash` here is 3.2, where an empty array under `set -u` fails, so use an `if`, not an empty `env` array.
2. **Compile** into a fresh `mktemp -d` folder (named in every message after this point), with the document's absolute path:
```bash
xcrun actool "$PWD/App/AppIcon.icon" --compile "$work" --platform macosx --minimum-deployment-target 15.0 \
    --app-icon AppIcon --output-partial-info-plist "$work/partial.plist" --target-device mac \
    --standalone-icon-behavior all --errors --warnings --output-format human-readable-text > "$work/actool.txt" 2>&1
```
A non-zero exit: `actool could not compile App/AppIcon.icon; what it said:` and `actool.txt`. A missing `xcrun actool` lands here too.
3. **Check what it made** (Review Focus 2). Without `Assets.car` or `AppIcon.icns`: `actool wrote no Assets.car or AppIcon.icns from App/AppIcon.icon; what it said:`. Then `CFBundleIconFile` and `CFBundleIconName` of `partial.plist` must equal those of `$app/Contents/Info.plist`, both `AppIcon`; otherwise `actool names the icon <file>/<name>, App/Info.plist names it <file>/<name>`. Then `assetutil --info "$work/Assets.car" > "$work/assetutil.json"` must have a `"Appearance" : "NSAppearanceNameDarkAqua"` line followed by `"AssetType" : "IconImageStack"`, and the line `"Name" : "AppIcon_Assets\/m-dark"`; otherwise `Assets.car holds no dark icon (assetutil's description: <path>)`.
4. **Swap in the solid M** (design 8.1, Review Focus 4): `iconutil -c iconset "$work/AppIcon.icns" -o "$work/AppIcon.iconset"`. Without `icon_16x16.png` in it: `AppIcon.icns has no 16-pixel picture to replace`. Then copy `App/AppIcon-16.png` over it and `iconutil -c icns "$work/AppIcon.iconset" -o "$work/AppIcon.icns"`.
5. **Copy in:** `mkdir -p "$app/Contents/Resources"`, copy `Assets.car` and `AppIcon.icns` there, and print `build-app.sh: icon: Assets.car (light and dark) and AppIcon.icns in Contents/Resources`.

**Interfaces:**
- `icontool <app> <out.png> <scale>` (scale 1 or 2; AppKit; built by the workflow with `swiftc -O` and signed ad hoc, like windowtool). It draws one sheet, 592 by 864 points at `scale` pixels per point, with no words, in three rows 288 points high:
  1. `NSWorkspace.shared.icon(forFile: app)` drawn inside `NSAppearance(named: .aqua)!.performAsCurrentDrawingAppearance`, on #FFFFFF;
  2. the same image drawn inside `.darkAqua`, on #1D1C1A;

  Each row holds the image at 16, 32, 64, 128 and 256 points, left to right, 16 points apart and from the edge, centred in the row. It prints `sheet <path> <w> <h>` and, per row, `reps <light|dark|icns> <pixel widths, comma separated>`. It exits 1 when the app or the `.icns` cannot be read or the PNG cannot be written. Its header comment says this, says it is CI only, and says it reads only.

It writes `pictures/<os>-icon-sheet-1x.png`, `-sheet-2x.png` and `-finder.png`, `<os>-icns/` (the `.icns` unpacked), `<os>-assetutil.json`, `icon.log`, and one line per check in `results.tsv`. | Check (results.tsv) | Reads | PASS when |
