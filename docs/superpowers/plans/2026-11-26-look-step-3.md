The script, beside `scripts/embed-host-script.sh` and built like it (`set -euo pipefail`, `cd "$(dirname "$0")/.."`, the same usage, `--check` with `cmp -s <(generate) "$out"` and the same three messages), reads `docs/superpowers/specs/look-2026-11-25/dotted-mountain.svg` and writes `Sources/MacMoshKit/Look/MountainArtTable.swift`. `generate` splits the file into tags (`tr '>' '\n'`) and reads them with `awk`: the `<svg` tag gives `width` and `height` (written `560.0`, `420.0`); each `<g fill="#…" fill-opacity="0.dd"` starts the next strength and appends its opacity to `strengths`; each `<circle cx="…" cy="…" r="…"/` adds one line `x, y, r, s,` with x and y in tenths (`112.5` → `1125`) and r in hundredths (`1.35` → `135`), made by joining the digits around the point, never by multiplying. It stops with a message naming the file for any other tag, a `cx` or `cy` without exactly one digit after the point, an `r` without exactly two, an opacity not of the form `0.dd`, or a drawing with no circle. The output is the same three header comments as `HostScriptSource.swift` (naming this script and the SVG), then `extension MountainArt {` with the four constants, one dot per line. The same drawing gives the same bytes. In `check.sh`, directly under line 20: `scripts/embed-dot-art.sh --check`; line 33 becomes `shellcheck scripts/embed-host-script.sh scripts/embed-dot-art.sh` (a trial merge of this change with step 5a's `check.sh` in a scratch folder had no conflict).
